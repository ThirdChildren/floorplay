## Project decisions

**Still valid**: D1–D64 (in particular D29–D30 persistence and life cycle, D31 joints and `pinch=`, D33 draw-call forecast, D40 preset phrases, D58 large text and high contrast, D63–D64), the user's gate rule of 2026-10-06 (blocking: errors in the console on the normal path, red tests/build, violations of `CLAUDE.md`, > 100 calls per view; the rest is a warning), the non-negotiable rules of `CLAUDE.md` (hands, seated, 60 fps, English, CC0, feature detection) and the calendar of `docs/ROADMAP.md`.

**D65 · Golden rule of phase A.** Everything phase A adds to the app is **behind `debug=1`** or **outside the app** (scripts in `scripts/quest/`, files in `qa/device/`). Without `debug=1` the behaviour, the logs, the draw calls and the saved state are **identical to M5**: this is proven by card S6.5 and by a test that compares every default of the tuning table with the original constant. No new dependency (`package.json`: only the `scripts` change), no asset, all texts in English in `src/ui/strings.ts` (`strings.debug`).

**D66 · Tuning knobs (T6.A1–T6.A4).** A single table in `src/logic/tuning.ts` (name, default, minimum, maximum, unit, "when it applies"), whose **defaults are the source of truth** and the old constants re-export them (no import cycle: `tuning.ts` does not import from the logic modules). The consumers read `getTuning().<name>` **inside the function**, never at import, so a change takes effect immediately or at the next opening. They are set with `t_<name>=<value>` in the URL and in `dev-params.local.txt` (keys with a prefix: `isQueryString` accepts them), **only with `debug=1`** (otherwise `tuning ignored ... reason=needs-debug`, like `failmy`); an out-of-range value is brought back to the limit (`tuning clamped`), an unknown or non-numeric name is discarded with `warn`; pairs with a constraint (`palmCloseDeg` > `palmOpenDeg`) are rejected with `reason=order`. **Live channel** (only `import.meta.env.DEV` with `debug=1`): the file `tuning.local.txt` (root, ignored by git, same format) is re-read every 2 s with `fetch(..., { cache: 'no-store' })`; a threshold is changed from the PC (`npm run quest:tune -- longPress=1.1`) **without leaving VR**. In the public build the file does not exist and the channel does not start. Precedence: live file > URL > default; a deleted or empty file brings back the values of the URL (`tuning cleared`).

**D67 · Which knobs, and which not.** The thresholds for which DEBT.md asks for high-priority tuning are included (list in the table below, 20 "essential" + 6 "optional"). **Not included**: (a) the **text scale** — it is a two-value switch (`text=normal|large`) with equality comparisons and cone tests that depend on `LARGE_TEXT_FACTOR`; the choice on the headset is which of the two values is the default, and if neither is enough, the fix is a task for `xr-engineer` (not a knob); (b) colours and contrast (binary, already `contrast=`); (c) the panel scale in general (same reason as (a)); (d) the parameters of the house geometry; (e) the rendering resolution (`framebufferScaleFactor`: fixed at session start; performance lever of D75, **to be verified** in IWSDK, not a phase A knob). `foveation` (D75) is included instead, because `WebXRManager.setFoveation` can be changed with a session open and, if it does not exist, the knob is a declared no-op.

**D68 · Statistics panel in the headset (T6.A8).** With `debug=1` and without `hud=0`, a UIKit panel `ui:debug-hud` **anchored to the world** (not to the head: a panel fixed to the head is annoying and falsifies comfort) to the left of the miniature, tilted towards the user, 0.55–0.85 m from the head, never above the miniature or above the panels (the cone test applies to the app's panels, **the HUD is exempt** and declares it). Content (English, one line each, updated **at 1 Hz**, only if the text changes): fps and time per frame (average, p95, maximum) with a status word (`OK` ≥ 70, `LOW` 60–69, `FAIL` < 60: not only colour); calls per view and triangles; joints source (`joints`/`grip`) and last pinch event; up to 4 lines of the log tail (also `warn`); minimum fps and worst frame of the session. The HUD **costs** a few draw calls: its cost is measured in the `hud` group of `[soglia:stats:groups]` (at the end of the line, as `sun` and `markers` did) and `hud=0` is the condition of **all final measurements** (D71). It is not an app interface: no field-of-view requirement, but it respects high contrast (`theme-contrast` checks every `.uikitml`).

**D69 · Scripts for the headset (T6.A9).** Node scripts in ESM, **with no new dependencies**, in `scripts/quest/`, with a pure and tested library of command builders (`lib.mjs`: `buildAdbArgs`, `buildOpenIntent`, `pickSerial`, `parseDevices`, `encodeLaunchUrl`) and `--dry-run`/`--serial` everywhere; it stops if `adb` sees more than one device without `--serial`. npm scripts (fixed names, `docs/QUEST_SETUP.md` sec. 11): `quest:check`, `quest:serve`, `quest:reverse`, `quest:unreverse`, `quest:open`, `quest:links`, `quest:tune`, `quest:console`, `quest:perf`, `quest:capture`, `quest:preview`. **Console of the headset from the PC (`quest:console`)**: if `typeof WebSocket === 'function'` (Node ≥ 22), the remote debugging port of the Quest Browser is forwarded (`adb forward tcp:9222 localabstract:chrome_devtools_remote`: **socket name to be verified**) and a session of the Chromium debugging protocol is opened (`Runtime.consoleAPICalled`, `Runtime.exceptionThrown`, `Network.requestWillBeSent` for the item "no request to a CDN"), writing the lines with a timestamp in `qa/device/logs/`; otherwise `adb logcat` filtered on `[soglia` (**to be verified** whether the Quest Browser writes the console there); otherwise stay on `chrome://inspect` (manual, always valid). This way Claude can **read** the console of the headset instead of asking the user to copy it. **No `playwright-core` imported directly** (it is an undeclared transitive dependency) and no `ws`.

**D70 · Browser feature probe (T6.A5).** A `[soglia:env]` line at start and, when the session starts, a `session` line. Only **feature detection** (rule 5): presence of interfaces (`'XRPlane' in window`, `XRAnchor`, `XRHitTestSource`, `XRMesh`, `XRHand`), `navigator.xr.isSessionSupported('immersive-vr' | 'immersive-ar')` (informative data: *no* session and no optional feature is requested), `SpeechRecognition`/`webkitSpeechRecognition`, `MediaRecorder`, `getUserMedia`, `navigator.virtualKeyboard`, access to `localStorage` (test write and read, with `try/catch`), secure context, short user agent (`OculusBrowser/<version>` or `HeadlessChrome/...`), **whether IWER is active** (result `iwer=yes|no`: **how to recognise it is to be verified**; it is tried with several clues, none based on the user agent alone), `session.enabledFeatures`, `frameRate` and `supportedFrameRates` **if they exist** (`n/a` otherwise), effective reference space, `cameras` (`views=2`), cold start time (`performance.now()` at "world ready" and at the first frame). No missing feature may throw an exception (test with everything `undefined`). The presence of an interface does **not** prove that the feature works: the log line says so (`anchors=iface`).

**D71 · Performance measurement.** Two conditions, always declared in the report: **tuning** (development server, `hud=1`, `debug=1`: indicative numbers, non-minified build, IWER not active) and **final measurement** (`npm run quest:preview`: production build, `debug=1&hud=0`, the numbers come from `[soglia:frames]` and `[soglia:stats]` read by `quest:console`; the GPU/CPU trace from `quest:perf` as a cross-check). Gate criterion: **no 2 s window below 60 fps** at any point of the demo, average fps ≥ 66 in the normal steps (goal 72), p95 of the time per frame ≤ 16.7 ms, worst case K18 included (`pinned` menu open + invalid `my-sofa` in hand + labels + markers) and the moment of `Furnish`. The fps of the headset depend on the refresh rate (72/90/120 Hz: **to be verified** with `session.frameRate`); it is always noted.

**D72 · Who changes the defaults.** The `quest-integrator` **proposes** the value with the numbers ("protocols" table), `xr-engineer` applies it in the table of `tuning.ts` (commit `fix(tuning): <name> 0.8 -> 1.0`, test updated). It is decided **only once per session**, at the end of the session, not during. After Thu 12 23:59 **only values** are changed (no new logic) and fixes ≤ 2 real hours; a bigger defect becomes a **declared limitation** (Devpost, `DEBT.md`) instead of a risky change in the last week.

**D73 · How the app is served to the headset.** Normal path, the one in the guide: `npx @iwsdk/cli dev up --no-open` (self-signed HTTPS on 8081, **certificate warning also on `localhost`**), `adb reverse tcp:8081 tcp:8081`, `https://localhost:8081/?debug=1`. `--native-xr-control` and `pair-headset` are **not** used in the sessions with hands; **only once in S0** (5 minutes) it is tried whether `pair-headset` (reading the ECS state from the PC) lets the real hands keep working: if so, it is a source for measuring the real distances of the panels from the real head (`ecs query` + head pose); if not, it is abandoned. The final measurement uses `quest:preview` (HTTP on `localhost`: secure context, **without** warning: to be verified).

**D74 · Mixed reality: cut, outside the gate (explicit decision).** `mr=1` is read from the parameters but **has no effect** (cut in M5, D53). For M6: the M5 item "mixed reality in two rooms" is **closed as ➖ not applicable**; it is not tested, not mentioned in the demo or in the Devpost as a feature; no smoke test of `mr=1` (it would do nothing). Only the information of `[soglia:env]` (`arSupported`, planes/anchors/hit test interfaces) remains to be noted in the report as data about the browser. Reopening the question would require a new feature after the freeze: **it is not done**.

**D75 · Performance levers, in order** (go down only if the final measurement does not pass D71): (1) right measurement: `hud=0`, production build, same point in two tests; (2) `t_foveation` (0 → 1: quality cost at the edges against GPU time; **value and default in IWSDK to be verified**); (3) one panel fewer (the `ui` and `markers` groups of `[soglia:stats:groups]` say where the calls go); (4) refresh rate (if 90/120 Hz is active for the browser, go back to 72); (5) lower `framebufferScaleFactor` (requires a configuration change at session start: **to be verified** in IWSDK, fix ≤ 2 h, not a knob); (6) give up an element (for example the wide room label in large text). Every step is measured before and after; no lever is applied "by eye".

**D76 · Tests on the headset: safety and rest.** Sessions of 2–3 hours with a 5-minute break every 25 of VR (arm fatigue with hand tracking falsifies the pinch measurements: the elapsed time is noted in the report), always **seated**, stationary boundary, no controller. The comfort tests (fade, real scale) are done **first** in the session and stop at the first discomfort.

**D77 · Evidence, not statements.** A row of `qa/device/DEBT.md` changes "Result on the headset" **only** with a reference to the report (`qa/device/M6-<date>-S<n>.md#<item>`) that contains the measurement or observation; "OK" requires the number (n tests / n successes, fps, millimetres, seconds). Never "works on the headset" for what was only seen in the emulator; M1–M5 become 🟩 only if **all** the `high` rows of the milestone are OK or justified as a declared limit.

**D78 · If the headset is late** (stepped fallback, "Calendar and fallback"): the freeze state does not change; the sessions are reduced to the P0 list (D79) and the tuning to three knobs; the rest goes into `DEBT.md` as **not tested**, declared in the Devpost.

**D79 · P0 list (everything stops if it fails).** (1) the app starts on the Quest Browser, the hands are visible, the emulator does not activate, no errors in the console; (2) the pinch does what it should (selection, grab, release) with the real hands; (3) the palm menu does not open by mistake and opens when needed; (4) fps ≥ 60 in the worst case; (5) real pause and resume; (6) the long pinch does not create a marker by mistake; (7) the panel texts can be read at 0.5–0.8 m. Every P0 defect takes precedence over any other test and opens an immediate fix (D72).
