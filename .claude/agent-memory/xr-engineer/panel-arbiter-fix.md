- Menu (pinned), View and Issues panels all open at the SAME anchor (`pinnedPanelAnchor`, 0.52 m, centred on the gaze), so any two open together overlap by > 50 % of the smaller one (test `panel-arbiter.test.ts`); two cannot sit side by side inside the 30 deg cone. Rule chosen: the last panel opened closes the others, same frame. Pure part `src/logic/panel-arbiter.ts` (`panelsToClose`, `panelWinner`, `panelsToReconcile`, `panelViewBox`/`viewBoxOverlap`), carried out by `src/systems/panel-arbiter.ts` (registry: `registerPanel`, `panelOpening(id)` after the refusal checks, `reconcilePanels()` per frame in palm-menu/View/Issues update). It replaced `onMenuOpening` and the `closeOpenMenu(); closeIssuePanel('panel')` chains; close `via=` strings are unchanged (menu opening -> `menu`, view/issues -> `panel`).
- NOT reproduced: before the fix the emulator never showed two of them open (debug keys, rapid sequences, palm path); old code was one-sided and lagged one frame (Issues.open did not close View, View closed itself next update). The reported overlap on the headset is unexplained: the new log lines `panel arbiter opened=X closed=Y` and `panel conflict kept=X closed=Y` say what happens there. Other candidates not touched: the fixed buttons sit 38 deg from the gaze (outside the cone) and a steep look-down opens the panel over the model.
- Scratch runtime while the user's Quest `vite` server is running (`dev up --no-open`, pid in `/tmp/iwsdk-*`): rsync the project to the scratchpad WITHOUT `.iwsdk`, `.mcp.json`, `.git`, `.claude`; make `node_modules` a real dir of per-entry symlinks (a symlinked `node_modules` shares the runtime state and `dev up` refuses); change `port` in the copy's `vite.config.ts`; `npx @iwsdk/cli dev up --ai-mode agent --workspace <copy>`; drive with `--workspace <copy>` CLI (`browser interact` press key, `xr set-transform` device `hand-right`, `ecs find`, `browser logs`), `dev-params.local.txt` in the copy. Add throwaway debug keys (F2 View, F3 Issues) only in the copy. `dev down --workspace <copy>` when done.

## Follow-up: pinned menu follows the gaze and keeps clear of the button column

- `src/logic/menu-follow.ts` (pure) + `src/systems/button-column.ts` (shared record written by menu-button, read by palm-menu) + `placePinned` in `src/ui/palm-menu.ts` (now per frame). Dead zone 12 deg heading / 10 deg pitch, glide tau 0.3 s max 90 deg/s, gap 3 deg to the strip (strip = widest of the 3 buttons x 3 buttons tall, seen from the head). Never crosses the strip (keeps its side), tie -> away from a right column (left of the user).
- Traps found by the property tests: (1) the elevation exemption (menu above/below the strip) made pushes jump up to 17 deg when a nod made the heights meet: fixed with a ramp (`ELEVATION_RAMP_DEG`, clearance scales 0..1); (2) a push must use the box of the menu AS IT WILL BE re-anchored from the live head (`menuBoxAt`), not the stale anchor, or head translation leaves a sliver of overlap; (3) `viewBoxOverlap(margin)` grows BOTH boxes: pass gap/2 for a gap of `gap`; (4) `uprightAnchorInCone` allocated a closure: made allocation-free (`blendAnchor`) because the follow runs it every frame.
- Looking straight at the buttons puts the menu ~25 deg to the side (outside the 30 deg cone, maxAngle ~47): the accepted price. View/Issues panels and the room-view buttons are NOT moved by this.

## Follow-up 2: View and Issues follow the gaze too

- `src/ui/pinned-follow.ts` (`PinnedFollower`) wraps `menu-follow.ts` + head reading; the menu, View and Issues UI classes each own one (`open(head, extent, large, column, tie)`, `step(...)` returns moved, `version` bumps). The systems pass `delta` + `getButtonColumn()` and re-place their control anchors when `panel.poseVersion` changes (View `placeAnchors` and Issues `placeAnchors` are idempotent: reuse anchors by id). The large-text "move along the gaze" lives in `pinnedPanelAnchor` (view-fit/menu-anchor), which the follower calls: one follower, not two. `isLargeText()` is NOT read per frame: use the panel's own fixed flag (`layout.large`, `panelScale()>1`, `menuScale>1`).
- Tests: `tests/unit/pinned-panels-follow.test.ts` runs the same property grid for all three panels (real extents). Room-view buttons / coach / hints were checked and are not the same bug: room buttons sit above the menu by elevation (shared +8 pitch clamp) and View/Issues never open at real scale; the coach banner hangs under the menu frame and moves with it.
