# TENANT: the tenant cannot move furniture, archived issues can be deleted (2026-11-17)

**Gate**: PC only (IWER headless, cloud machine, SwiftShader: fps 7-9 mean nothing). Branch `main`. **Nothing here was tried on a headset**:
see the TENANT rows of `qa/device/DEBT.md`.

Checks before each commit: `npm run typecheck`, `npm test` (161 files, 7065 tests passed, 1 skipped), `npm run build`.

## What changed

- `src/logic/permissions.ts`: new action `furnish` (visitor, agent, landlord; **not** tenant) and `delete` (tenant, landlord). `can(role, 'delete', issue)`
  is true only for an `issue` entry with status `archived`. Every other role and action is exactly as before.
- `src/logic/state.ts`: `placeFurniture`, `moveFurniture`, `removeFurniture`, `undo` and `stageFurniture` are ignored while the role cannot `furnish`
  (so no path can edit the furniture as tenant). `setFurniture` (the `furnish=` URL and set-up code) and the restore are not user actions and stay open.
  New `deleteIssue(id)`: only an archived issue, only `can(role, 'delete', issue)`; `nextIssue` and `issuesSeeded` are untouched, so the id is never reused and
  the demo seed (applied once, `issuesSeeded`) never comes back.
- Systems: `furniture-grab` does not claim the pinch for the tenant (so the long pinch on top of a piece still creates a pin) and drops a held piece if the role
  loses `furnish`; `menu-items` / `palm-menu` show no tabs and no cards and the heading "View only" (`strings.menu.locked`), Undo is faint and does nothing;
  `rotate-button`, `room-pieces` (My room) and the first-minute `coach` do nothing for the tenant. The Issues panel detail has a Delete button for an archived issue:
  first press arms it ("Press again to delete"), second press deletes, logs `issue deleted id=... by=...` and goes back to the list.
