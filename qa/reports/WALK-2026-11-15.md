# WALK: walking inside the tabletop model with the dig gesture (2026-11-15)

**Gate**: PC only (IWER headless, cloud machine, SwiftShader: fps 8-13 mean nothing). Branch `claude/dig-walk`. Plan `docs/plans/WALK.md`,
scenario `qa/scenarios/WALK-dig.md`. **Nothing here was tried on a headset**: see the WALK rows of `qa/device/DEBT.md`.

Checks run before each commit: `npm run typecheck`, `npm test` (157 files, 6916 tests passed, 1 skipped), `npm run build`.

## How the gesture was exercised

IWER's synthetic hand is open and palm down, and its joints are read by the same `fillPoses` code the app uses on a headset, so the
REAL recognition path ran in the emulator: the wrist of each hand was moved with `IWER_DEVICE.hands.left|right.position.set(...)` from a
page-side loop (a stroke back and forth) while `window.__sogliaWalk.status()` was sampled. The `xr animate-to` CLI cannot make a two-hand
stroke (the runtime serialises the two calls). Fingers cannot be bent in IWER, so fist and pinch-pose rejections are unit tests only.
`window.__sogliaWalk.drive(speed, seconds)` (`?debug=1`) was used to feed a speed through the same step, collision, vignette and store
code for the wall and door checks, so those checks prove everything after the gesture, not the gesture.

## Findings and decisions

- The model is magnified around the head, not the user shrunk: see decision 1 of the plan (it keeps all UI working).
- The smoothing of the wrist speed (60 ms) lets the last frame of a stroke add a little speed after the hands stop; harmless.
- IWER runs at 8-13 fps here, so `dt` is clamped to 0.1 s; on a headset the strokes will be sampled much better, so the gain may
  need lowering (DEBT row "Speed and comfort").
