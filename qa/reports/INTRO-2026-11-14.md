# INTRO · Start screen, house file, furniture sizes, Enter VR (PC gate)

Date: 2026-11-14 · Branch: `claude/intro-menu` · Runtime: IWER emulator, headless Chromium (`dev up --ai-mode agent --headless --allow-browser-automation`) · Scenario: `qa/scenarios/INTRO-start-screen.md`

**Verdict: PC-done for the checks below. Nothing was tried on a headset** (rows added to `qa/device/DEBT.md`).

## What was built
- Start screen (plain DOM over the canvas, `src/ui/intro-screen.ts`): title, selected house card, `Load house file`, `Furniture`, `Enter VR`. 72 px buttons, 64 px steppers, text 22 px (28 px with large text), black background with `contrast=1`, `prefers-contrast: more` honoured, visible focus ring, buttons have accessible names.
- Load house file: the existing homes section (`mountHouseFiles` in `src/ui/house-file-panel.ts`) lives inside the start screen. A kept file becomes the selected house (the page opens again with `?house=file-<id>`); `Use this house`, `Remove` (two presses) and the demo houses work as before.
- Furniture: the 14 `furniture` items of the catalog, width / depth / height in cm, `-` / `+` (5 cm) and a number box, limits from `src/logic/catalog-sizes.ts` (a quarter to three times the catalog size, 5-400 cm width and depth, 1-300 cm height, flat pieces stay flat), `Reset to default` per item and `Reset all to default` (two presses). Saved under `soglia:v1:catalog-sizes` (memory fallback, feature-detected), read once at load and applied to a copy of the catalog.
- Enter VR: calls `launchXR` from the press. The SDK offer is switched off while the start screen is on (`withoutSessionOffer`). The button is disabled with a message when the world is not ready, the house failed to load, or the browser has no WebXR.
- `intro=0|1` URL parameter (default 1); `intro=0` keeps the old entry.

## Decisions
- **Sizes and `reset=1`: kept.** The sizes (like the houses loaded from a file) are the user's settings, not the saved state of a house, so `clearSogliaKeys` skips `soglia:v1:catalog-sizes`. QA that needs catalog sizes starts from a clean profile or uses "Reset all to default" (documented in `docs/DATA_FORMATS.md`, `CLAUDE.md`, `qa/README.md`).
- **Sizes are applied by reopening the page.** The catalog is read once at load and many systems hold it; instead of a live update (menu, models, collisions, pieces already placed) the Furniture screen shows `Apply and go back`, which reloads the page with the same house (`reset` dropped from the URL). With no usable `localStorage` the sizes stay in memory only, and the screen says that they cannot be applied.
- **The selected house is the URL** (`house=`), as before. Selecting a house or loading a file reopens the page, so the world behind the start screen is always the selected house and Enter VR needs no slow work (a session can only be requested from a user gesture).
- The world is built behind the opaque start screen; the first frames are not shown.
- glTF models of a resized piece are scaled non-uniformly from `defaultSize` to `size` inside a group (same shared geometry, no new draw call); fallback blocks are built at the new size.
- Existing scenarios (M0-M6, MR) assume the offered session: they need `intro=0` (note in `qa/README.md`); the scenario files were not edited one by one.

## Notes from the run
- `browser interact` reports `success: false` (no `completed` steps) for the click that reloads the page (`Apply and go back`, `Use this house`, the house upload); the navigation happens anyway. Check the logs (`catalog sizes applying`, `params ...`) instead.
- The file upload needs the Playwright runner (`--allow-browser-automation`, `browser run` with `setInputFiles`); `browser interact` has no upload action.
- Heavy `reset=true` in `dev-params.local.txt` is re-applied after `Use this house` (the page URL drops `reset`, the dev file does not): a test artifact only.

## Not done / limits
- Not tried on a headset: the Quest Browser 2D page with hand pointing, the file picker there, the virtual keyboard for the number boxes, the session granted from the button (see the INTRO rows in `qa/device/DEBT.md`).
- No automated DOM tests (the unit environment is Node, no jsdom); the screen is covered by the emulator run above and by the pure logic tests.
- A house kept in memory only (storage full or blocked) cannot be selected, as before: selecting reloads the page and the house would be lost.
- The selection is not remembered across visits to the bare URL (it is `house=` in the URL, default `apartment-a`).
- `contest-reviewer` was not run.
- Older scenarios were not changed; they need `intro=0` (see `qa/README.md`). `qa/device/presets.json` and `scripts/quest/*` were not changed.
