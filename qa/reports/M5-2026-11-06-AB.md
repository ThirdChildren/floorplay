- Runtime `npx @iwsdk/cli dev up --ai-mode agent --headless`, `browserCommandReady: true` after about 1 minute. For each scenario: `dev-params.local.txt` (one line) -> `browser reload` -> `xr enter` -> `xr set-input-mode hand` -> wait 3 s -> head (0; 1.6; 0) identity, hands at rest (-0.30; 1.10; 0.10) and (0.30; 1.10; 0.10). All starts with `reset=1`, except where the scenario tests resuming.
- `pinch=grip` calibration: the recipe `T - D_GRIP` = `(Tx+0.038; Ty+0.003; Tz-0.037)` centered all the buttons and chips (8 x 6 cm); for the washer (long pinch) the T5.8 measurement `T + (0.029; -0.0015; -0.045)` worked (`draft created at=0.42,0.85,5.05 fixture=washer` on the first try). `pinch=auto`: hand at `T + (0; 0.0245; 0.012)`; the log `[soglia:hands] ... event=pinch-start point=` gave exactly the target (for example `point=-0.130,1.437,-0.465` on V1, `point=-0.130,1.400,-0.465` when I got the marker's y height wrong: V1 is at y = 1.4375, not 1.40, and the selection does not fire).
- My buffer filter: the `browser logs` pattern is a regular expression **without case sensitivity**: `NaN` finds `tenant`, `state` finds `[soglia:state]` (huge). To read the `[soglia:state]` state I used the pattern `soglia:state\\]` with `count 1`.
- The `ui:tabletop-button` button (and all anchored panels) is read **after** putting the head back to yaw 0: after a yaw of 180 degrees for the screenshot the button stays behind and the pinch misses.
