### T0.5 · Data consistency beyond the schema — owner: `logic-tester`
- **Files**: `tests/unit/data-consistency.test.ts` (new).
- **Dependencies**: T0.3, T0.4.
- **Do** (for each house; the checks that the schema cannot express):
  - unique ids (rooms, walls, openings, viewpoints, fixtures) within the house;
  - every opening fits within the wall length (`offset + width ≤ length`, axis-aligned walls) and two openings of the same wall do not overlap;
  - `connects` of every door points to existing rooms or to `"outside"`; **only one** door with `entrance: true`;
  - every room is reachable from the entrance door on the door graph;
  - viewpoints and fixtures fall inside the polygon of their room (`room` exists);
  - room polygons are clockwise (consistent signed area) and have no repeated vertices;
  - `staging[*][*].catalogId` exists in `catalog.json`; the staging positions fall inside a room polygon;
  - issues: `houseId` = an existing house, `fixtureId` (if present) exists among the fixtures of that house and `position` is inside the bounding box of the house; issue ids unique;
  - history: `history[0].event === 'created'` and non-decreasing dates;
  - known values from `docs/DATA_FORMATS.md`: `d-living` = 0.80 m and `d-bathroom` = 0.75 m in A (they are the data on which the FitCheck of M3 relies).
- **Note**: if a check fails on real data, the tester does **not** modify the data: it opens the report for `xr-engineer` with the failing test.
- **PC acceptance**: `npm test` green with ≥ 25 assertions on data; failures, if any, listed with file and id.

## Risks and alternatives

| Risk | Impact | Alternative / mitigation |
|---|---|---|
| Vitest loads `vite.config.ts` and starts the IWSDK bridge | slow tests or tests that open processes | dedicated `vitest.config.ts` (T0.2); if the plugin loads anyway, launch with `--config vitest.config.ts` in the script |
| `ajv` / `ajv-formats` ESM-CJS interop in Vitest | failing imports | `import Ajv from 'ajv'` and `addFormats.default ?? addFormats`; alternatively `createRequire` |
| Playwright/headless Chromium not installed for `dev up --ai-mode agent` | gate 3 blocked | `npx playwright install chromium` (ask the user if network/sudo is needed); as a fallback `--ai-mode collaborate` with a visible window (announce it) |
| Port 8081 busy | `dev up` fails without moving | `npx @iwsdk/cli dev down`, then retry; if that is not enough, find the process with `ss -ltnp` |
| `defineAssets({})` rejected | build broken after the cleanup | a single minimal procedural asset instead of empty (to be verified with `iwsdk-reference`) |
| **URL parameters not reachable from the MCP tools** | all the scenarios with `?house=...` cannot run | not an M0 problem but it becomes one in M1: the `browser_*` tools do not navigate to arbitrary URLs ("This tool does not navigate to arbitrary URLs"). Solution planned in `M1.md` T1.2 (development-only override file). Alternatively check `--allow-browser-automation` of `dev up` |
| The CI on GitHub cannot be tried from the PC | gate 4 only static | the user does the first push and confirms green; until then it is "statically verified" in the report |
