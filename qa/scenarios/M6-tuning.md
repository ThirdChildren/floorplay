> **Changelog 2026-11-07**: scenario created from the M6 plan (D65, D66, D67; T6.A1–T6.A4, T6.A10). > **Changelog 2026-11-07 (evening, T6.A12, after the implementation)**: (1) the **live file `tuning.local.txt` needs the `t_` prefix** (`t_pinnedDistance=0.62`); without the prefix it is ignored **without any log line**; (2) the 6 optional knobs **are all wired** (`tuning table count=26`); (3) when a name leaves the live file but stays in the same lower layer or goes back to the default, `tuning set <name>=<default> default=<d> source=default` appears; a live file that is not `a=1&b=2` gives a single `tuning file ignored reason=not-a-query` (warn); (4) `foveation`: `tuning foveation applied=<v>`, `restored=<v>` (when removed), `skipped reason=no-api|failed`; (5) **passing through the URL (`window.location.search`) cannot be proven with the emulator tools** (they do not open pages with a query): here the source is `source=file` (`dev-params.local.txt`); the URL is covered by unit tests; (6) `fov-mask` exists **only in a session**; (7) **artifact to tolerate**: an `error` line of type `requestfailed` `GET …/tuning.local.txt net::ERR_ABORTED` if Playwright reloads the page during a poll (tool artifact, only with `debug=1` in development): filter on `kind: requestfailed`, it is not a FAIL; (8) `pinnedDistance`/`pinnedDrop` apply to the normal-text panel; (9) values measured by the engineer in the headless emulator: default → `miniature placed` y=1.350 z=−0.450 and distance 0.59; with `t_pinnedDistance=0.65&t_anchorForward=0.55&t_anchorDown=0.30` → y=1.300 z=−0.550 and distance 0.68; clamp 3→0.75 → distance 0.78; marker V2 at 3.2 cm from the center: no transition by default, transition with `t_viewpointRadius=0.045`; marker recipe: world position = `miniature:root.pos + scale × (local + house position)` with the house shifted by (−5.5; 0; −3.6), that is V2 at (0.065; 1.4375; −0.47) at the default placement, hand = point − `D_GRIP`; the **F7** key (with `debug=1`) opens and closes the `pinned` menu and `menu view maxAngleDeg=… distance=…` is the reading.

**Milestone**: M6 (phase A) · **Type**: PC (IWER emulator via MCP `iwsdk-runtime`) · **`CLAUDE.md` rules**: 3 (performance), 4 (resume), 5 (feature detection: `foveation`) · Plan: `docs/plans/M6.md`.
Implementation prerequisites: T6.A1–T6.A4 (step 7 also T6.A10). Conventions: `qa/scenarios/M5-gate-notes.md` (standard setup, `pinch=grip` hand calibration: the hand to pinch `T` goes to `T − D_GRIP`, `D_GRIP` = (−0.038; −0.003; +0.037)).
**What is NOT tested here**: the **time and angle** knobs (`longPress`, `palmOpenHold`, `palmOpenDeg`, …) cannot be measured in IWER (MCP latency of 1–3 s, exact poses, no tremor): for these the unit tests (the consumer follows the value) and the `tuning set` log line apply. Here only the **geometric and deterministic** effects are tested.

## Conventions
- M5 standard setup for each step: write `dev-params.local.txt` (one line), `browser_reload_page`, `xr_accept_session`, `xr_set_input_mode {mode: "hand"}`, wait 3 s, head at (0; 1.6; 0), hands at rest (∓0.30; 1.10; 0.10).
- `BASE` = `house=apartment-a&role=visitor&reset=1&seed=1&debug=1&pinch=grip&time=2026-12-21T10:00`.
- The live file is `tuning.local.txt` in the **project root** (one line, same format; ignored by git).
- The `pinned` menu opens with a pinch on the button `ui:menu-button-right` (`ecs_query_entity` with `["Transform"]`, right hand at `T − D_GRIP`, `xr_select {duration: 0.3}`); it closes with the same button. The distance is in the line `menu view maxAngleDeg=… distance=…`.

## Steps
1. **Reference (defaults)**. `dev-params.local.txt` = `BASE`. Readings: log `pattern: "tuning|params|miniature placed"` → line `tuning table count=<n> debug=true`, no `tuning set` line, line `params …` without `hud=0` or anything else at the end compared with M5; `miniature placed` → `O0` (expected x=0, y=1.350, z=−0.450). Open the `pinned` menu: `menu view … distance=D0` (expected ≈ 0.59). Close. Marker: `ecs_query_entity` `viewpoint:V2` with `["Transform"]` → `M2`; right hand at `M2 + (0.032; 0; 0) − D_GRIP`, `xr_select {duration: 0.3}`, wait 2.5 s: log `pattern: "viewpoint"` → **no** line `viewpoint transition start id=V2` (radius 0.025 < 0.032). If the pinch selects a room or starts a drag, note it (it is not a FAIL).
2. **Knobs from the file**. `dev-params.local.txt` = `BASE&t_pinnedDistance=0.65&t_anchorForward=0.55&t_anchorDown=0.30&t_viewpointRadius=0.045`, reload. Log `pattern: "tuning|miniature placed"` → four lines `tuning set <name>=<value> default=<d> source=file`. `miniature placed` → y=1.300 and z=−0.550 (head at 1.6; 0). Open the `pinned` menu: `distance` ≈ 0.68 (√(0.65² + 0.20²) = 0.680 ± 0.01), `maxAngleDeg` read and noted (it may exceed 30°: **not a FAIL**, it is the declared consequence of the value). Pinch at `M2 + (0.032; 0; 0)` as at step 1 (the marker is now in another position: reread `M2` with `ecs_query_entity`): log `viewpoint transition start id=V2 from=tabletop` **present**. Go back to the model (`ui:tabletop-button` or reload).
3. **Limits, wrong names, constraints**. `dev-params.local.txt` = `BASE&t_pinnedDistance=3&t_bogus=1&t_longPress=abc&t_palmOpenDeg=50&t_palmCloseDeg=45`, reload. Log: `tuning clamped name=pinnedDistance requested=3 applied=0.75` (warn), `tuning ignored name=bogus reason=unknown` (warn), `tuning ignored name=longPress reason=not-a-number` (warn), `tuning set palmOpenDeg=50 …`, `tuning ignored name=palmCloseDeg reason=order` (warn; the processing order is that of the table; if the engineer chose another, what is written in "Outcomes" of `docs/plans/M6.md` holds). No exception, no `error`. Open the `pinned` menu: `distance` ≈ 0.80 (√(0.75² + 0.20²) = 0.776 ± 0.01).
4. **Without `debug=1` the knobs do not apply**. `dev-params.local.txt` = `house=apartment-a&role=visitor&reset=1&seed=1&pinch=grip&t_pinnedDistance=0.65&t_longPress=1.2` (no `debug`). Log: at least one line `tuning ignored name=… reason=needs-debug` (warn) for each name, **no** `tuning set`, no `tuning table`; open the `pinned` menu: `distance` = D0 (default; the `menu view` line exists even without `debug`). No `[soglia:stats]` line.
5. **Live channel (without reloading)**. `dev-params.local.txt` = `BASE`, reload, XR session active. Open the `pinned` menu: `distance` = D0, close. First negative test: write `tuning.local.txt` with `pinnedDistance=0.62` (**without** `t_`), wait 3 s: **no** new `tuning` line (it is ignored without a log) and `distance` still D0. Then write `tuning.local.txt` with `t_pinnedDistance=0.62`; wait 3 s (the poll is every 2 s): log `tuning set pinnedDistance=0.62 default=0.55 source=live`; `xr_get_session_status` → `sessionActive: true` (**no reload**). Reopen the menu: `distance` ≈ 0.65 (√(0.62² + 0.20²) = 0.651 ± 0.01). Write a file with two valid entries and one invalid (`t_pinRadius=0.03&t_pickMargin=0.02&t_zzz=1`): the valid ones apply (`source=live`), the invalid one gives `tuning ignored name=zzz reason=unknown`. Then rewrite the file **removing** a name (`t_pinRadius=0.03` only): `tuning set pickMargin=0.015 default=0.015 source=default` appears (the name that went back to the default). A file that is not a query (`hello world`) gives **a single** `tuning file ignored reason=not-a-query` (warn) and does not change the values. **Delete the file**; wait 3 s: log `tuning cleared`; reopen the menu: `distance` = D0 (the file values go back to the URL defaults). The poll does not exist in the production build (no `fetch` toward `tuning.local.txt`: see S6.4 step 10).
6. **Foveation**. `BASE&t_foveation=0.5`: log `tuning foveation applied=0.5` (in IWER the engineer saw it applied) **or** `tuning foveation skipped reason=no-api|failed` (+ `feature renderer.xr.setFoveation unavailable`): both PASS; no `error`. From the live file: remove `t_foveation` → `tuning foveation restored=<v>` (or no line if it had not been applied). With `t_foveation=7` → `tuning clamped name=foveation requested=7 applied=1`.
7. **Field-of-view mask**. `BASE&t_fovMask=30`, XR session: log `fov-mask on halfAngleDeg=30` (**only in a session**: before `xr_accept_session` 0 entities); `ecs_find_entities` `^debug:fov-mask$` → 1; `browser_screenshot` → attach (black ring at the edges, free center); `[soglia:stats]` `callsPerView` = that of step 1 + 1 (±1) and the `hud=` group of the `[soglia:stats:groups]` line goes up by 1 (the mask counts in the `hud` group; with the HUD on `hud=3`). With `t_fovMask=0` or without the parameter: 0 entities. Change from the live file `t_fovMask=45`: `tuning set fovMask=45 … source=live`, `fov-mask on halfAngleDeg=45` without reloading; deleting the file: `tuning cleared` and `fov-mask off`.
8. **Defaults unchanged**. Reload with `BASE` without `t_*` and redo step 1 (distance D0) and the pinch of the marker at 0.032: the outcomes are those of step 1.
9. Unfiltered log (`error`, `uncaught`, `Cannot read`, `reading 'add'`, `Missing glyph`, `budget exceeded`): no line beyond the intended `warn`s of steps 3, 4 and 5; cleanup (`dev-params.local.txt` and `tuning.local.txt` removed).
