# S6.4 · Scripts for the headset (`npm run quest:*`), without a headset

> **Changelog 2026-11-07**: scenario created from the M6 plan (D69; T6.A9, T6.A11). It is run **without a headset and without `adb` connected** (also on the cloud machine): everything with `--dry-run` and with exit codes. The `adb`/`metavr` commands printed are those **to be verified on the headset** (`docs/plans/M6.md`, R61–R63): here the form is checked, not the effect. This scenario uses the shell, not the MCP tools of the emulator.

> **Changelog 2026-11-07 (evening, T6.A12, after the implementation)**: (1) the scripts are **11** (`check`, `serve`, `reverse`, `unreverse`, `open`, `links`, `tune`, `console`, `perf`, `capture`, `preview`), all with `--dry-run`; `--serial` applies to `check`, `reverse`, `unreverse`, `open`, `console`, `perf`, `capture`; (2) **`adb shell` quoting (trap)**: the remote command is **a single argument** with the URL between double quotes, printed as `adb -s TEST123 shell 'am start -a android.intent.action.VIEW -d "https://localhost:8081/?…&…"'` (with outer single quotes: without them, an `&` would start a background job on the headset); steps 2, 3 and 5 are rewritten accordingly; (3) the dry-run **reads** `npx @iwsdk/cli dev status` for the port (read-only, ~0.6 s) and shows it as `port <n> from dev status|--port|default`; (4) `quest:console` writes `qa/device/logs/console-<date>-<time>.log`, channel `cdp` (Node 22+) or `logcat`; (5) `quest:perf` and `quest:capture` accept extra words after `--` and have as working folder `qa/device/traces/` and `qa/device/captures/` (both ignored by git); (6) `lib.mjs` has **51 tests** in `tests/unit/quest-scripts.test.ts`, which also launches the scripts with `--dry-run`, with `PATH=''` and with a fake `adb` with two devices (step 5 can therefore be rerun with that test); (7) **12 presets**; `perf-worst` carries `hud=0`; (8) T6.A11 is delivered: `quest:links` generates `public/dev/quest.html` with **relative** links (`../?query`); URL `https://localhost:8081/dev/quest.html`; (9) the scenario is not run in the emulator: it runs in the shell, also on the cloud machine (without `adb`: step 1 without dry-run must give code 1 and an English message).

**Milestone**: M6 (phase A) · **Type**: PC (shell) · **`CLAUDE.md` rules**: no heavy dependency without asking, everything in English · Plan: `docs/plans/M6.md`.
Implementation prerequisites: T6.A9 (and T6.A11 for step 9). Run from the repository root.

## Steps
1. **`quest:check`**. `npm run quest:check -- --dry-run` prints the commands it would run (`adb devices -l`, `adb reverse --list`, the server status) and ends with code 0 without running them. `npm run quest:check` (without dry-run) on a PC **without a headset** ends with a code ≠ 0 and **a message in English** that says what is missing (`adb` not found or no authorized device) and what to do (pointer to `docs/QUEST_SETUP.md`); no stack trace.
2. **`quest:reverse` and `quest:unreverse`**. `npm run quest:reverse -- --dry-run --serial TEST123` prints `adb -s TEST123 reverse tcp:8081 tcp:8081`; `quest:unreverse` prints `adb -s TEST123 reverse --remove tcp:8081`. Without `--serial` and with the port read from `dev status` or from `--port`: the port is always the one of the status, never fixed at 8081 if the server says otherwise (`--port 8082` is reflected in the command).
3. **`quest:open`**. `npm run quest:open -- smoke --dry-run --serial TEST123` prints `adb -s TEST123 shell 'am start -a android.intent.action.VIEW -d "https://localhost:8081/?…&…"'`: **a single remote argument between single quotes, with the URL between double quotes** (the `&`s of the URL stay inside the quotes; if the outer quotes are missing it is a FAIL: the `&` would cut the command); `--mode vr` prints the VR launch (`am broadcast -n com.oculus.vrshell/.ShellControlBroadcastReceiver -a com.oculus.vrshell.intent.action.LAUNCH -d apk://com.oculus.browser -e uri "ovrweb://vr?uri=<encoded URL>"`) with the inner URL **encoded** (`?` → `%3F`, `&` → `%26`, `:` → `%3A`, `=` → `%3D`: no bare `&` or `?` after `uri=`). A full URL as an argument (`https://localhost:8081/?debug=1`) is accepted; a URL with a host other than `localhost` or the network IP is rejected with a clear message.
4. **Unknown preset**. `npm run quest:open -- nope --dry-run`: code ≠ 0, message `unknown preset` with the list of valid presets.
5. **Two devices**. With a fake `adb` in a temporary folder of the PATH (shell script that prints two serials `AAA111 device` and `BBB222 device` for `devices -l`): `npm run quest:check` and `quest:open -- smoke` **stop** with a message that asks for `--serial` and do not choose; with `--serial BBB222` they proceed. (The unit test `pickSerial` proves it; here it is seen with the CLI.)
6. **`quest:links` and the presets**. `npm run quest:links` prints all the presets of `qa/device/presets.json` (at least `smoke`, `a-clean`, `b-clean`, `tenant`, `landlord`, `agent`, `sun-winter-10`, `sun-summer-14`, `contrast-text`, `grip`, `perf-worst`, `resume`) with the full URL and writes `qa/device/links.md` (file in English). `npm test -- quest-scripts` is green and proves that **every preset query** passes `parseParams` and `parseTuningText` **without any warning** and that `resume` does not contain `reset=1`.
7. **`quest:tune`**. `npm run quest:tune -- longPress=1.1 palmOpenHold=0.6` writes in `tuning.local.txt` exactly `t_longPress=1.1&t_palmOpenHold=0.6` (one line, final newline); `npm run quest:tune -- --clear` deletes the file; `npm run quest:tune -- bogus=1` exits with code ≠ 0, message `unknown tuning name` with the list, and does **not** touch the file; an out-of-range value is written as is (the clamp belongs to the app) but the script warns. `git check-ignore tuning.local.txt` → ignored.
8. **`quest:console`, `quest:perf`, `quest:capture`, `quest:preview`, `quest:serve`** with `--dry-run`: `quest:console` says which channel it would use (debug protocol if `typeof WebSocket === 'function'`, otherwise `adb logcat`) and where it would write (`qa/device/logs/console-<date>-<time>.log`); `quest:perf -- --seconds 10` prints `npx metavr perf capture --app com.oculus.browser --mode vr --duration 10000` (subcommand and flags **to be verified** with `npx metavr perf --help`: if the engineer chose otherwise, what is written in "Outcomes" of `docs/plans/M6.md` holds) and the folder `qa/device/traces/`; `quest:capture -- shot` and `-- video` print the `npx metavr capture` command; `quest:preview` prints the sequence `npm run build` + `vite preview` on port 4173; `quest:serve` prints `npx @iwsdk/cli dev up --no-open`. None of these runs `adb` or `metavr` with `--dry-run`.
9. **Start page** (T6.A11). `npm run quest:links` creates `public/dev/quest.html` (in English, HTML and CSS only, large links one per preset, **relative** `../?query`, no port written); `git check-ignore public/dev/quest.html` → ignored; with the server on, `curl -sk https://localhost:8081/dev/quest.html` answers 200 and contains the 12 presets; `npm run build` and then: `dist/dev/` **does not exist**, `dist/qa/` and `dist/scripts/` do not exist.
10. **Build hygiene**. `npm run build` green; in `dist/` no file `tuning.local.txt`, `presets.json`, `links.md`, `quest.html`.
11. **Dependencies**. `git diff -- package.json` (or comparison with `jq`): **only** the `scripts` section changes (`quest:*` additions); `dependencies` and `devDependencies` identical to M5; `package-lock.json` unchanged.
12. **Language and accents**. `grep -rnE "[àèéìòù]" scripts/ qa/device/presets.json public/dev 2>/dev/null` → no line (scripts, presets and page are in English; comments included).
13. **Consistency with the guide**. Every `quest:<name>` cited in `docs/QUEST_SETUP.md` (section 11) exists in `package.json`, and every name `t_<name>` of the table of section 11.2 exists in the table of `src/logic/tuning.ts` (the optional names that are not wired are removed from the guide by T6.A12). Suggested command: `grep -o "quest:[a-z]*" docs/QUEST_SETUP.md | sort -u` compared with `jq -r '.scripts | keys[]' package.json | grep quest`.
